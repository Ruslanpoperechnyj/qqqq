**Дата:** 2026-10-05  
**Этап:** первичный обзор завершён; статический аудит исходников финалистов продолжается.  
**Облачный scope для сравнения:** широкий — Entra/M365, Azure, AWS и GCP. Это решение о границах исследования, а не разрешение на запуск, admin consent, назначение ролей или изменение tenant.

## Результат в двух словах

Наиболее сильные дополнения — узкие локальные слои: (1) анализ уже собранного BloodHound-графа, (2) предметная проверка AD ACL и AD CS, (3) Entra application-identity review и облачный posture-аудит с безопасным подмножеством проверок, (4) браузерный crawler для современных SPA. Очередной автономный pentest-агент не нужен. Любой будущий запуск подключённых средств — только через ASM gates, закреплённый scope, лимиты и аудит.

### Не считать новыми возможностями или не включать сейчас

- **RustHound-CE 2.5.22 и SharpHound 2.17.0:** в обоих просмотренных исходниках есть WebClient probe. RustHound проверяет активные компьютеры через SMB `IPC$` и `\PIPE\DAV RPC SERVICE`; метод входит в `All`. Это активные, журналируемые соединения и **не уникальное покрытие RustHound**. Tag RustHound указывает на commit `9ea48da22be634928b02d05eb0886d27181255e2`, но unsigned (`verified_tag: false`); SHA архива и ref записаны в `download_manifest.json`. Нужны ASM gates.
- **ADRecon:** привилегированный сбор может включать LAPS-пароли и BitLocker recovery keys; не подходит по текущим правилам обращения с секретами. AGPL-3.0; код давно не обновлялся.
- **GPOZaurr/Testimo:** в рассмотренных материалах не подтверждена permissive/commercial license; Gallery указывает “All rights reserved”.
- **PingCastle Community:** Non-Profit OSL ограничивает платные оценки третьих организаций без коммерческого grant. **Locksmith:** MIT + Commons Clause создаёт риск платной услуги, зависящей от инструмента.
- **Purple Knight/Forest Druid:** закрытые локальные продукты; source review невозможен, остаются EULA/регистрация/анонимность и точный охват.
- **PentAGI, Strix, Shannon, AIDA, Dark Moon, CAI:** полезны как архитектурные источники, но автономный shell/HTTP/эксплуатация не подключаются к цели напрямую. Issues, release notes и видео — не независимый аудит. Dark Moon: GPLv3 badge, но формальный root LICENSE не найден; CAI архивирован, LICENSE содержит отдельные research-only/non-commercial компоненты.

## Текущие результаты статического аудита

- **AD-Miner 1.9.0:** обычный запуск вызывает `requests.get("https://www.ad-miner.com/version.json", timeout=0.5)`. В просмотренном вызове не передаются данные цели, но внешний сервер видит IP/время обращения. В Neo4j пишутся `g.dangerous_inbound` и `r.cost`; если найден GDS, перечисляются и удаляются существующие графы через `gds.graph.drop`. `anon_graphdb.py` отдельно переписывает атрибуты узлов. Это не «offline/read-only» инструмент относительно подключённой базы.
- **ADACLScanner 9.6:** правильный entrypoint в архиве — `ADACLScan.ps1` (не `ADACLScanner.ps1`). Просмотренный код использует LDAP SearchRequest и механизм подписанного/запечатанного LDAP с LDAPS fallback; LDAP modify/add/delete операции не найдены. Отдельная функция GUI загружает baseline CSV с `raw.githubusercontent.com/.../refs/heads/main` по нажатию, не как обязательный telemetry path. Запрос к этому baseline-серверу раскрывает IP/факт скачивания; данные AD по проверенному коду не отправляются.
- **Certipy 5.1.0:** `find` читает шаблоны, CA, OID и ACL через LDAP. Без `-dc-only` он подключается к CA по SMB Remote Registry для чтения конфигурации и делает HTTP(S) probe `/certsrv/`; HTTPS channel-binding проверяет двумя аутентифицированными GET (NTLM/Kerberos) при `verify=False`. Поэтому `find` — не только DC LDAP scan; CA fan-out должен быть явно в scope. Остальные команды пакета не входят в разрешаемый профиль.
- **Maester 2.2.97-preview:** по умолчанию `Invoke-Maester` вызывает `Write-Telemetry`, который POST-ит на `https://us.i.posthog.com/capture/` event `InvokeMaester` и `distinct_id = TenantId` (либо `unknown`); opt-out — `-DisableTelemetry`, который действует и при `-NonInteractive`. Для PowerShell Gallery нужна отдельная оговорка: `Invoke-Maester -NonInteractive` пропускает финальную version-check, но `ConvertTo-MtMaesterResult` всё равно получает latest version через Gallery OData, если явно не передан `-SkipVersionCheck`; этот флаг надо задавать отдельно. Локальный report object содержит TenantId/TenantName/Account, сведения о машине и пользователе, OS/PowerShell, загруженные модули и параметры/конфигурацию; при Graph-подключении report также делает GET баннера организации. Не выгружать и редактировать как чувствительные данные. `Connect-Maester -Service All` не включает AD/GitHub; `New-MtMaesterApp`, `Update-MtMaesterApp`, `Set-MaesterAppPermission` и `Add-MtMaesterAppFederatedCredential` содержат Graph POST/PATCH и создают/меняют tenant-объекты, appRoleAssignments и federated credentials. `Update-MtMaesterTests` может удалить совпадающие файлы тестов перед копированием (после подтверждения либо с `-Force`). Эти helper-команды не использовать; tenant ID в телеметрии несовместим с полной анонимностью без opt-out и egress deny.
- **ZAP Client Side Integration 0.32.0:** в просмотренном `ClientSpider` обнаруженные формы планируются к `SubmitForm`, где вызывается `form.submit()`; `ClickElement` нажимает A/BUTTON/INPUT и другие pointer-interactable элементы. `ScopeCheck.FLEXIBLE` — default и разрешает third-party ресурсы proxy-трафику, хотя их не crawl-ит; `STRICT` блокирует их, но не запрещает same-origin действия. `logoutAvoidance` по умолчанию включён, но фильтрует только клики по текстовым индикаторам; form-submit ветка его обходит.
- **AzureHound 3.1.1:** просмотренные `list`-коллекторы используют Graph/ARM GET и выводят JSON в stdout/локальный файл; чтения значений Key Vault через data-plane endpoint не найдено. Для `list apps` запрос идёт в `/v1.0/applications` без `$select`; полный `azure.Application` помещается в `models.App`, чей `MarshalJSON` меняет регистр нескольких полей, но не фильтрует `PasswordCredentials`/`KeyCredentials`. Модель допускает `PasswordCredential.SecretText` и `Hint` (первые 3 символа), а также `KeyCredential.Key` (public certificate bytes); `SecretText` обычно возвращается только в ответе на addPassword, а не list, но если поле будет в ответе, оно сериализуется. Поэтому `list apps` — только условный кандидат после sanitizer/проверки; весь JSON чувствителен. Команда `start` отправляет данные в BloodHound Enterprise и исключается как SaaS.
- **Entra App Exposure 1.0.0:** Graph transport принимает только GET; batching отправляет внешний POST к `/$batch`, но строит внутренние подзапросы как GET. Токен берётся app-only client-secret flow через `login.microsoftonline.com`; в snapshot credential-объектов сохраняются тип/KeyId/имя/сроки, но не SecretText/private key. Вывод и snapshots локальные и чувствительные. Live assessment требует `Directory.Read.All` и отдельного app consent, который не разрешён.
- **Prowler 5.44.0:** `Check_Report` конвертирует dataclass через `asdict`, Pydantic-ресурсы через `.dict()`, а `Finding` переносит весь `check_output.resource` в `resource_metadata`. Для AWS SSM `SSM.__init__` загружает список собственных документов и вызывает `GetDocument` для каждого, сохраняя JSON `Content` в объекте `Document`. `ssm_document_secrets` сканирует этот content; и он, и `ssm_documents_set_as_public` отдают целый `Document` в `Check_Report`, поэтому body с командами и потенциальными hardcoded secrets попадёт в report. Исключить весь SSM service из allowlist, а не только secret-check; `secrets_validate` не включать (по умолчанию false). Проверенный Key Vault service читает метаданные, не значения секретов.
- **NetExec 1.5.1:** успешные SMB/LDAP credentials добавляются в SQLite; инструменты выполнения команд и многочисленные модули не соответствуют модели узкого read-only помощника. `audit_mode` — редактирование отображения секрета, а не защита от модулей/изменений.

## Вывод для безопасного профиля (только по коду, запуск не разрешён)

- **Maester:** если оператор отдельно разрешит оценку, минимум — `-DisableTelemetry -SkipVersionCheck -NonInteractive`, заранее выбранный узкий набор тестов, без app setup/permission helpers/consent/role grants и без рассылки отчётов. `-NonInteractive` сам по себе не отключает PostHog и не гарантирует отключение Gallery lookup; явные opt-out флаги и отдельное блокирование PostHog/Gallery нужны; для доступа к цели отдельно разрешать только одобренные Graph endpoints. Report сохранять локально и защищать/редактировать: в нём есть tenant/account и Graph-context metadata, параметры/конфигурация, а также имя машины/пользователя, OS и загруженные модули.
- **ZAP Client Spider:** в просмотренных Options/Automation/API не найден read-only переключатель, который отключает submit/click. В текущем виде не использовать как unattended crawler по реальному scope. `STRICT` ограничивает только out-of-scope ресурсы; от same-origin submit/click не защищает. Допуск возможен лишь в изолированной лаборатории либо после отдельного interaction gate/патча и проверки, что опасные действия подавляются; `logoutAvoidance` не заменяет такой gate.
