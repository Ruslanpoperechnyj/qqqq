# ASM — свой аналог «CVE.Global» для небольших заказов

Рабочий прототип платформы анализа внешнего периметра (EASM), повторяющий функции
инструмента из видео «ВЕСЬ МИР УЖЕ ВЗЛОМАН». Написан на чистом Python 3 — без зависимостей,
без Docker, без платных API.

```
python3 app.py serve          # дашборд на http://localhost:8000
```

Прототип уже проверен на реальном хосте: собирает поддомены, открытые порты, технологии,
сопоставляет версии с NVD, приоритизирует по CVSS × EPSS × CISA KEV и формирует отчёт
для заказчика с указанием основания работ.

---

## 1. Что именно делают в видео и что сделано здесь

| В видео | Как это устроено внутри | В этом прототипе |
|---|---|---|
| «Видит весь интернет», поиск по IP/странам/технологиям | Собственный индекс баннеров: сканирующая сеть + БД на годы | `collect.py`: crt.sh (CT-логи), InternetDB (публичный индекс баннеров), RIPEstat, DNS-over-HTTPS, RDAP |
| «Анализ инфраструктуры за 7 секунд» | Предрасчёт + кэш + корреляция справочников | `scan.py` + SQLite-кэш: повторный анализ того же объекта идёт мгновенно |
| «На IP — CVE 2023 года, подключение не защищено» | Баннер/версия → CPE → сопоставление с NVD | `identify.py` → `cve.py` (точный запрос NVD по CPE версии) |
| «Предиктор анализирует, каким действиям инфраструктура подвержена» | Скоринг по CVSS/EPSS/KEV + экспозиция | `score.py`: объяснимая формула с P0–P3 |
| «ИИ объясняет простыми словами, приоритет защиты, сценарий атаки» | LLM поверх структурированных данных | `ai.py`: оффлайн-режим (шаблоны+правила) и LLM-режим (любой OpenAI-совместимый эндпоинт) |
| «Инфраструктурный профиль, карта связей» | Граф домен→IP→ASN→сервис→технология | `store.py` (edges) + граф в дашборде (SVG, силовая укладка) |
| «Слепок человека по цифровым следам» | OSINT по людям | **Сознательно не реализовано** — это уже не аудит периметра, а обработка ПДн (152-ФЗ) |

## 2. Быстрый старт

```bash
# 0. Один раз: бесплатный арсенал ИБ (19 инструментов). Полная установка ~4 минуты.
bash bin/install-tools.sh
bash bin/install-tools.sh --fast          # только ядро (разведка, порты, проверки) — ~1,5 минуты
python3 app.py engines                    # что установлено, какая версия, чем что закрывается

# 1. Дашборд
python3 app.py serve                      # http://localhost:8000

# 2. Через CLI
python3 app.py add client.ru --client "ООО «Ромашка»" --ref "Договор №14-А от 12.05.2026"
python3 app.py scan client.ru             # полный анализ: 10 этапов, ждёт завершения
python3 app.py scan client.ru --no-wait   # то же, но в отдельном фоновом процессе
python3 app.py scan 2                     # по номеру цели (число — это всегда ID ЦЕЛИ, не скана)
python3 app.py findings 1                 # находки P0/P1
python3 app.py report 1 --out client.md   # отчёт заказчику
python3 app.py list                       # цели и анализы
python3 app.py engines                    # арсенал: 19 инструментов, версии, шаблоны, словари
python3 app.py drafts 19                  # черновики проверок nuclei по находкам анализа
python3 app.py search 19 "старое шифрование"   # поиск по находкам по смыслу (локальная модель)
```

Материалы заказчика для внутренней проверки (код, репозиторий, образ контейнера):

```bash
python3 app.py scan client.ru --repo https://github.com/client/site.git
python3 app.py scan client.ru --code /home/audit/client-site
python3 app.py scan client.ru --image registry.client.ru/site:2.3
```

Полезные переменные окружения:

```bash
export NVD_API_KEY=...        # ускоряет обогащение CVE в 10 раз (бесплатный ключ на nvd.nist.gov)
export ASM_LLM_BASE=http://localhost:11434/v1   # Ollama / OpenAI / vLLM — для ИИ-собеседника
export ASM_LLM_MODEL=huihui_ai/qwen3-abliterated:14b   # локальная модель без цензуры
# необязательно: ASM_TG_TOKEN + ASM_TG_CHAT (или ASM_WEBHOOK_URL) — уведомления о завершении

export ASM_ACTIVE_SCAN=0      # отключить активный этап (по умолчанию включён)
export ASM_ACTIVE_TIMEOUT=600 # предел времени на активные проверки, секунды
```

## 3. Конвейер: десять этапов

(Полный список шагов с привязкой к инструментам — `АРСЕНАЛ-ИБ.md`, раздел 2.)

```
1. Discover  crt.sh            — поддомены из логов выдачи сертификатов (объект не трогаем)
2. Resolve   DNS over HTTPS    — какие имена реально отвечают, в какие IP
3. Enrich    InternetDB+RIPE   — открытые порты, CPE-версии, CVE-имена, ASN/провайдер/страна
4. Probe     HTTP/TLS          — ОДИН запрос на веб-порт: заголовки, титул, сертификат
5. Identify  правила           — Server / X-Powered-By / meta generator / cookies / порты → продукт+версия
5b. Active   naabu + nuclei     — свои порты (не из чужих индексов) и проверки уязвимостей по шаблонам
6. CVE       NVD+KEV+EPSS      — CPE версии → ровно те CVE, что касаются этой версии
7. Score     формула           — приоритет P0..P3 с объяснением каждого множителя
8. Diff      сравнение         — что появилось/исчезло с прошлого анализа (мониторинг)
9. Report    правила или LLM   — резюме для руководителя, приоритет, сценарий, план на неделю
```

Важная деталь из этапа 3–4: **всё, что можно, берётся пассивно** (из публичных индексов),
и только по веб-портам делается по одному лёгкому запросу. Никакого перебора, никакой
эксплуатации. Это и есть разница между «анализом» и «сканированием», о которой говорит
автор видео: при сканировании вы стучитесь в объект, при анализе — читаете то, что объект
сам публикует для подключения.

### Активный этап (5b): когда «анализ» уже недостаточно

Публичные индексы знают не всё: закрытый периметр, свежие сервисы и внутренние адреса
там не видны. Поэтому по команде инструмент умеет **сам** пройти по согласованным адресам:

* **naabu** — сканирование портов (SYN, при нехватке прав — обычное соединение);
* **nuclei** — проверки по 13 000+ шаблонам (уязвимые версии, открытые служебные файлы,
  конфигурация, дефолтные учётные записи, захват поддоменов, технологии).

Встроенные ограничения — чтобы не навредить: исключены категории `dos`, `fuzz`, `intrusive`,
`brute-force`; перебор паролей и эксплуатация не выполняются; лимит скорости 80 запросов/с,
предел времени 600 с, не больше 12 адресов за один прогон. Отключается одной переменной
`ASM_ACTIVE_SCAN=0`. Кнопка «активные проверки» есть и в дашборде.

### Как закрыть: рекомендации к каждой находке

Инструмент не только находит проблему, но и объясняет, что делать. К **каждой** находке
прикладывается блок «Как закрыть»: класс проблемы, шаги по-русски, команды и куски конфигов
(Apache/nginx/SSH/MySQL/Redis/Docker/WordPress…), а также чем проверить результат.
В отчёте для заказчика из этого собирается сводный план на неделю, сгруппированный по типам работ.

## 4. Источники данных и их статус

| Источник | Что даёт | Нужен ключ | Правовой статус |
|---|---|---|---|
| `crt.sh` | поддомены, сертификаты, УЦ | нет | публичные логи CT |
| `dns.google` (DoH) | A/AAAA/MX/TXT/NS/CNAME | нет | публичный DNS |
| `rdap.org` | регистратор, владелец, даты | нет | публичный RDAP (замена WHOIS) |
| `stat.ripe.net` | префикс, ASN, оператор, страна | нет | публичные данные маршрутизации |
| `internetdb.shodan.io` | порты, CPE, теги, CVE | нет | публичный индекс (free-tier Shodan) |
| `services.nvd.nist.gov` | CVE, CVSS, диапазоны версий | необязателен | открытые данные NIST |
| CISA KEV | факты эксплуатации в атаках | нет | открытые данные CISA |
| `api.first.org` | EPSS — вероятность эксплуатации | нет | открытые данные FIRST |
| HTTP/TLS-проба | заголовки, версии, сертификат таргета | — | **активное действие: только по письменному разрешению владельца** |

## 5. Как считается «приоритет защиты»

```
база      = CVSS²            (9.8 → 96, 7.5 → 56, 5.9 → 35, 4.3 → 18)
экспозиция: TLS ×1.10 · HTTP ×1.15 · небанальный порт наружу ×1.20
EPSS:      ≥50% ×1.30 · ≥10% ×1.15 · ≥1% ×1.05
техдолг:   ≥5 лет +8 · ≥2 лет +4
score     = база × множители + техдолг

P0 ≥ 85 или CISA KEV (эксплуатация уже фиксируется)   — закрыть за 24–72 часа
P1 ≥ 55                                              — 1–2 недели
P2 ≥ 28                                              — плановое обновление
P3 <  28                                             — к сведению
```

Любое число в отчёте можно защитить перед заказчиком: в `rationale` расписано,
из чего сложилась оценка, и у каждого множителя есть источник (NVD / FIRST / CISA).
Именно это отличает инструмент от «ИИ предсказал уязвимость»: предсказание тут —
не магия, а прозрачный скоринг по публичным метрикам.

## 6. ИИ-слой: как это работает на самом деле

В видео ИИ «понимает» найденное и объясняет словами. Технически это две разные вещи:

1. **Оффлайн-режим** (по умолчанию, `ai.py`): из структурированных данных собираются
   «Резюме для руководителя», «Приоритет защиты», «Сценарий атаки», «План на неделю»
   по правилам и шаблонам. Работает без интернета и без ключей, результат детерминирован.
2. **LLM-режим**: тот же срез данных (JSON: находки, CVSS/EPSS/KEV, ASN, изменения) уходит
   в модель через OpenAI-совместимый API, и она пишет текст «для человека».

Модель **не ищет** уязвимости — она объясняет то, что нашли инструменты. Если вы захотите
локальную модель без интернета: `ollama pull qwen2.5:14b` и `ASM_LLM_BASE=http://localhost:11434/v1`.

## 7. Ограничения метода (то, что нужно знать перед показом заказчику)

* **Ложноположительные по CPE.** В дистрибутивах Linux уязвимости часто закрываются backport-патчами
  без смены версии — по базе NVD компонент «уязвим», фактически — нет. Каждую находку P0/P1
  подтверждайте вручную перед работами. (В прототипе для этого есть второй фильтр диапазонов и
  таблица `REFINED_RANGES` в `asm/cve.py` — расширяйте её по мере практики.)
* **NVD бывает неточен.** Иногда диапазон версий задан слишком широко; в прототипе такие записи
  фильтруются повторной локальной проверкой, а самые известные — уточняются вручную.
* **Свежесть данных об открытых портах.** InternetDB — снимок, может отставать на дни/недели.
* **Не видно того, что закрыто.** Если сервис за VPN или требует авторизации, пассивный анализ
  его не покажет — для этого нужен активный пентест по отдельному согласованию.
* **EPSS/KEV меняются.** В отчёте фиксируется дата анализа.

## 8. Как это встроить в ваши заказы

1. **До работ.** Письменное разрешение: домены/IP, срок, кто со стороны заказчика отвечает.
   В инструменте это обязательные поля `заказчик` + `основание`; без них анализ не запустится,
   а каждый запуск пишется в журнал аудита (кнопка «Журнал» в дашборде). Для подрядчика в РФ это
   не бюрократия, а разделение «аудита» и ст. 272 УК РФ.
2. **Первый анализ** — 5–15 минут для небольшой компании. Результат: отчёт .md для заказчика,
   .csv для трекера, .json для интеграций.
3. **Повторные анализы** раз в 2–4 недели: раздел «Изменения» показывает новые активы и новые
   находки, а также закрытые. Это то, за что берут абонентскую плату — контроль, а не разовый отчёт.
4. **Допродажа.** Отчёт даёт естественный список работ: обновление компонентов, закрытие БД/VPN,
   вынос тестовых сред, аудит доступа к панелям, резервное копирование.

## 11. Что добавлено во второй итерации (04.10.2026)

**Сканирование всей инфраструктуры по одному адресу (`estate.py`).**
Вводите один адрес — инструмент сам добирает остальное: типовые имена (словарь из ~120 вариантов),
почтовые и служебные хосты из NS/MX, домены из SPF, обратные имена для IP,
а по флагу «сети организации» — анонсированные префиксы автономной системы адреса и ближайшие к
подтверждённым адреса из этих сетей (с предупреждением: сети могут содержать чужие адреса).
Лимиты: `ASM_ESTATE_WORDS`, `ASM_ESTATE_MAX_HOSTS`, `ASM_ESTATE_MAX_PREFIXES`,
`ASM_ESTATE_PREFIX_IPS`, `ASM_ESTATE_MAX_EXTRA_IPS`, включение — `ASM_ESTATE=1`, сети — `ASM_ESTATE_ASN=1`.

**Клик по элементу → карточка → разговор.** Граф: поиск, масштаб, перетаскивание узлов,
сохранение расположения, сохранённые виды, подсветка «путей до риска» (кратчайшие маршруты от
точек входа до узлов с находками P0/P1). Карточка: находка, актив, порт, сервис и **кнопка
«Проверить заново»** — точечная перепроверка своего же адреса (свежий ответ сервера прикладывается
к журналу аудита) и **«Мнение ИИ»** — структурированный вердикт «подтверждено / ложное /
недостаточно данных» с указанием, чем подтвердить.

**Триаж и дисциплина работы.** Статусы находок (открыто, подтверждено, ложное, принято в риск,
закрыто) с пометкой и ответственным; статусы и отпечаток доказательства переносятся на повторные
анализы, исчезнувшие находки помечаются закрытыми автоматически. Реестр активов: критичность,
доступ, ответственный, метки, заметка — **критичность актива двигает приоритеты его находок**
(контекст бизнеса, как в SSVC).

**Процесс.** Планировщик регулярных анализов (`/api/schedule`, интервал в интерфейсе), уведомления
(Telegram/webhook — выключены по умолчанию), «Сводка для руководителя» на один экран.
Поиск по находкам переведён на полнотекстовый FTS5 с запасным вариантом по подстроке.

**ИИ-модуль.** Поток SSE (`context` → `token` → `done`), ограничение частоты, очистка недоверенного

## 11д. Что убрано из отчёта заказчику (03.10)

Отчёт читает не инженер, а руководитель заказчика — поэтому из текста вычищено всё, что
выдаёт «внутренности» платформы:

- **Никаких путей на машине аудитора.** Раньше в графе «Объект» можно было увидеть
  `/tmp/asm-repo-gyhecgum/repo/package-lock.json`; теперь — `package-lock.json`. Копия
  репозитория создаётся во временном каталоге, и этот каталог заказчику знать незачем.
- **Никаких словарей Python.** Раздел «Изменения с прошлого анализа» печатал
  `{'what': ..., 'asset': ..., 'port': None}`; теперь это читаемые строки вида
  «CVE-2021-40438 — 45.33.32.156:80», не более 12 пунктов на блок, остальное — «…и ещё N».
- **Адреса, найденные перебором имён файлов, отделены от инфраструктуры.** Записи вида
  `…/nosuchurl/><script>alert` — это следы проверок, а не новые сервисы заказчика;
  они больше не попадают в список «Новые активы», о них сказано отдельной строкой с числом.
- **Шаги сценария атаки идут подряд.** Была сквозная нумерация с пропусками («Шаг 1 → Шаг 4»),
  когда промежуточных условий не срабатывало. Теперь нумерация по факту — пропусков не бывает.

## 11г. Как запускается анализ из командной строки (03.10)

`python3 app.py scan <цель>` **ждёт до конца** — это поведение по умолчанию, потому что в
99 % случаев от анализа хотят результат, а не «команда завершилась успешно».

- `--no-wait` запускает анализ **отдельным процессом** (журнал пишется в `scan-<номер>.log`
  рядом с проектом). Это не «нить внутри команды»: раньше нить умирала вместе с командой,
  а запись скана оставалась в состоянии «идёт» навсегда — казалось, что анализ идёт, хотя
  не шло ничего. Теперь процесс настоящий и отделён от терминала.
- Число в `scan` — это **ID цели**. Если ввести ID скана, команда скажет об этом прямо и
  подскажет номер цели.
- Сканы, оставшиеся в статусе «идёт» после перезапуска окружения, при следующем старте
  панели помечаются как **прерванные** (процессы сканов перезапуск не переживают) — в
  интерфейсе у них своя подпись и подсказка «запустите заново», чтобы это не выглядело
  как ошибка самой проверки.

## 11в. Почему арсенал живёт в `build/tools`, а не в `~/.cache` (04.10)

Это не мелочь, а условие того, чтобы проект вообще сохранялся между сессиями.

- Каталоги **вне** папки проекта (`~/.cache/asm-tools`) окружение стирает при перезапуске —
  арсенал исчезал.
- Но если положить все 19 инструментов **в** проект, снимок workspace раздувается:
  13 742 шаблона nuclei + правила Semgrep + сам trivy = **914 МБ и 20 869 файлов**
  при лимите 128 МБ / 10 000 файлов. Снимок перестаёт сохраняться: теряется всё, включая код.
- Решение: арсенал ставится в `<проект>/build/tools` — **внутри** проекта (значит,
  восстанавливается и не теряется), но под именем `build`, а такие каталоги в снимок
  не включаются по определению. В снимке остаются код, документы, база результатов
  и словари: **1 402 файла / 35 МБ**.
- Служебные кэши движков (`PDCP_DIR`, `NUCLEI_CACHE_DIR`, `XDG_CACHE_HOME`, сессии Wapiti)
  тоже уведены в `build/tools` — домашний каталог больше не мусорится, а `cpan`-кэш
  (43 МБ) заменён точечной установкой модуля `XML::Writer` прямо в каталог арсенала.
- Восстановление после перезапуска — одна команда (её же видно в подсказке при старте):
  `bash bin/install-tools.sh` (полный) или `--fast` (ядро). Установка идемпотентна:
  уже стоящее не перекачивается, а частично распакованный набор шаблонов (после обрыва)
  определяется как неполный и докачивается.

## 12. Правило безопасности (одно, короткое)

Активные проверки (сканирование портов и шаблонные проверки) допустимы **только** для
инфраструктуры, на которую у вас есть разрешение владельца — письмо или договор. Пассивный
анализ открытых источников разрешения не требует. Эксплуатация найденного и перебор паролей
инструментом не выполняются и добавляться не будут.
