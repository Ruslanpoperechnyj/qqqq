## 2. Ограничения

### 2.1 Природные — то, что не обойти

1. **Детект возможен всегда, и договор его штрафует.** Вход под настоящей учётной
   записью (а другой у вас нет) оставляет запись в журнале входа — по определению.
   Полная невидимость недостижима; речь о минимизации следов и согласованном окне.
2. **EDR неизвестен.** До первого доступа защита видна только косвенно; узнаём
   после (без привилегий, модуль `enum_av`), и только потом строим цепочку.
3. **Канал внутрь есть, но за одобрением** (§40, уточнено 08.10.2026). Агент
   отправляет команды сам — WinRM для Windows, SSH для Linux, один хост на шаг;
   каждая команда заново проходит ворота на отправке, ничего не кладётся на хост.
   Скорость работы больше не равна скорости оператора — равна скорости его
   решений; это и есть задуманное: «шаг без одобрения не выполняется».
4. **12 ГБ видеопамяти.** Модели 26B+ не влезают; потолок — ~12B в Q4/QAT.
5. **Жёсткий потолок полки — 225 GB.** Предварительный известный subtotal —
   ~141 GB, включая GOAD-Mini (~40), Kali (~12,2), BloodHound/Docker (~10),
   Greenbone CE (~60) и основную Gemma; ещё ~84 GB надо сверить по закреплённым
   версиям, Windows media и фактическим Docker/VM томам. `weakpass_2a` исключён.
   Полный Wazuh/Elastic-стек остаётся вне первой волны; подробности и checker — §44.
6. **«Бесплатно и без карты» = нет своего сервера.** Выход — VPN (Proton),
   приём обратных соединений — публичные серверы interactsh (узнаваемы),
   своего узла и редиректора нет.
7. **Песочница без сети.** Я не проверяю живые прогоны; всё живое — на вашей машине.
8. **Следы переноса файлов.** Имя payload (linpeas, SharpHound) — подпись; Sysmon
   видит создание файла и запуск вместе. Переименование не спасает — это проверено.

### 2.2 Искусственные — наши сознательные правила

Снимаются только вашим решением; по умолчанию держатся в коде, а не на честном слове.

1. **Одна дверь одобрения.** Ни один шаг не выполняется без явного решения
   человека. Автоодобрения нет ни в каком виде — ни по таймауту, ни при сбое модели.
2. **Необратимое ставится в очередь, но не выполняется без вас.** Решение
   оператора (04.10.2026): планировщик может предложить и шаг получения
   доступа, и внутренние шаги — очередь это ещё не разрешение. Дверь осталась
   прежней и живёт в коде: `agent.execute` без явного одобрения отказывает.
   Прежнее поведение возвращается настройкой `ASM_QUEUE_IMPACT=0`.
   Внутренние шаги не ставятся до записи доступа (после — ставятся: «где мы и
   от чьего имени», с хостом и учёткой из записи).
3. **Один хост — одно решение.** Шаг перемещения принимает ровно один хост; список
   отклоняется, и отклоняется до попадания в план.
4. **Агент останавливается на получении доступа** и передаёт его вам. Данные
   заказчика не изменяются; сбор секретов с 06.10.2026 разрешён отдельным
   документом — см. п. 16.
5. **Нет персистентности, C2, веерного перебора учёток, движения без цели в маршруте.**
6. **Kill switch обязателен.** Одно нажатие: убить живые деревья процессов и
   запретить запуск новых — всем сессиям, потому что флаг лежит в базе.
7. **Эксплуатация — только проверенным инструментарием.** Эксплойты, написанные
   LLM, не используются; sqlmap / шаблоны nuclei / Metasploit по имени модуля —
   в рамках согласованных проверок.
8. **Логи не трогаем.** Удаление исключено вашим решением; подмена и правка —
   отказался строить, позиция не отменена.
9. **Профиль `safe` по умолчанию** (щадящие скорости). `pentest`/`full` — осознанный
   выбор на конкретную работу.
10. **Скрытность по умолчанию `off`**; включает только исходящий трафик и каденцию,
    логи не трогает вовсе.
11. **Панель без аутентификации** — ваше решение; условие: слушать `0.0.0.0`
    только в доверенной сети (README §12).
12. **Планировщик на модели выключен по умолчанию** (`rules`). Предсказуемость
    важнее; включается осознанно.
13. **InternetDB** оставлен по вашему решению, хотя лицензия — «не коммерческое».
14. **Никакой соц. инженерии, стилеров/RAT/вредоносов на людей.**
15. **Чужая инфраструктура — вне объёма, не трогать никогда.**
16. **Секреты — разрешены документом (06.10.2026).** Прежний запрет `creds` снят:
    работа с секретами и чужими сессиями допустима. Ворота ведут себя так:
    `ASM_CREDS=block` (по умолчанию) — как раньше; `ASM_CREDS=approved` — шаг
    проходит как предупреждение с флагом одобрения, а громкие методы (дамп
    LSASS и подобное, `procdump lsass`, `comsvcs minidump`, `ntdsutil activate` —
    «только в согласованное окно»; тихие пути — файлы вроде `/etc/shadow` и
    `SAM`/`SYSTEM`/`SECURITY`). Взамен — **обязательство**:
    весь добытый доступ и секреты передаются заказчику лично до окончания срока
    работ (строка в `handover.py`; проверка `outstanding` — в работе).

**Режим работ одним словом** (хранится в базе, действует на каждую следующую
команду; проверка готовности — только для боевого, откат в тихий не блокируется):

| команда | что делает |
|---|---|
| `python3 app.py mode` | что сейчас и действующие значения ключей |
| `python3 app.py mode check` | готовность: самопроверка СТОП, движки, ответ модели, прикрыт ли выход |
| `python3 app.py mode combat` | боевой: профиль pentest, план модель+правила, скрытность warn, очередь разрешена |
| `python3 app.py mode safe` | тихий: как по умолчанию |
| `... mode combat --force` | включить поверх блокеров — осознанно, с записью в журнал |

Явная настройка сильнее режима: `--set ASM_PROFILE=full` перекрывает режим на запуск.

### 3.2 Что запускать, а что нет (этапы и источники)

| переключатель | по умолчанию | смысл |
|---|---|---|
| `ASM_ENGINES` | `1` | арсенал движков (nuclei, httpx, subfinder, dnsx, tlsx, katana, gau, ffuf) |
| `ASM_ENGINE_CRAWL` / `ASM_ENGINE_ARCHIVES` | `1` / `1` | обход ссылок (katana) / адреса из архивов (gau) |
| `ASM_FFUF` | `0` | перебор путей — самый шумный шаг, по умолчанию выключен |
| `ASM_NIKTO` / `ASM_TESTSSL` / `ASM_WAPITI` | `1` | проверки веб-сервера / TLS / приложения |
| `ASM_AMASS` | `0` | ещё один сборщик имён (долгий) |
| `ASM_ESTATE` / `ASM_ESTATE_ASN` | `1` / `0` | расширение «по адресу — вся инфраструктура» / сети организации |
| `ASM_TRUFFLEHOG_VERIFY` | `0` | проверка живости найденных ключей (ключ уходит владельцу сервиса) |
| `ASM_AUTO_LEARN` | `1` | автоматически запоминать уточнения по ложным срабатываниям |
| `ASM_SOURCES` / `ASM_SOURCES_OFF` / `ASM_SOURCES_EXTRA` / `ASM_SOURCES_PAUSE` | пусто | список «только эти», выключить перечисленные, включить нестабильные, пауза между источниками |

### 3.4 Скрытность (каналы выхода)

| переключатель | смысл |
|---|---|

### 3.7 Таймауты (~30 настроек одного рода)

`ASM_HTTP_TIMEOUT` (15 с, запросы к источникам), `ASM_ACTIVE_TIMEOUT` (600 с — общий
потолок активного этапа) и отдельные потолки движков: nuclei 900, naabu 240,
httpx 420, katana 180, nmap 240, nikto 180, wapiti 300, testssl 240, tlsx 180,
semgrep 900, trivy 600/900, trufflehog 600, osv 600, amass 240, gau 120,
gitleaks 300, ffuf 180. Смысл у всех один: **сколько ждать движок, прежде чем
считать, что он не ответит**. Если на объекте медленно — поднимать точечно.

### 3.8 Флаги командной строки (важные)

| флаг | где | смысл |
|---|---|---|
| `--set КЛЮЧ=значение` | везде | задать настройку одной строкой (можно несколько раз) — **единственный способ из PowerShell** |
| `--settings` | везде | показать все 128 настроек и их значения |
| `--port` / `--host` | `serve` | порт и адрес панели (по умолчанию `0.0.0.0:8000`) |
| `--planner rules\|model\|both` | `agent extend` | разово выбрать планировщика |
| `--scan` | `agent extend` | по какому скану подбирать план |
| `--operator` / `--note` | `agent`, `kb`, `verify`, `handover` | кто и почему принял решение (в журнал аудита) |
| `--limit` | `agent start/extend`, `drafts` | сколько шагов предложить |
| `--deadline` | `agent start/deadline` | жёсткий срок сессии (после — не выполнится ничего) |
| `--inside-host` / `--inside-user` / `--inside-os` / `--goal` | `agent inside` | параметры внутреннего шага (хост, учётка, система, цель) |
| `--no-wait` | `scan` | запустить анализ и не ждать в терминале |
| `--repo` / `--code` / `--image` | `scan` | материалы заказчика для проверки кода и образа |
| `--fmt md\|json\|csv` / `--out` | `report` | формат и куда писать отчёт |
| `map <сессия>` / `--mermaid` / `--out` | `map` | карта объекта: что известно о цели (собрано кодом). Текстом, схемой mermaid или файлом; `--target <id>` — без сессии |
| `--extra` | `sources` | нестабильные источники (RapidDNS, Wayback) |
| `--dry-run` | `kb learn` | показать, что было бы запомнено, ничего не менять |
| `--index` | `memory` | пересобрать индекс памяти между объектами |

### 3.9 Кнопки в панели

- **СТОП** — тот самый kill switch (`/api/agent/stop`): убивает живые деревья
  процессов и запрещает запуск новых.
- **Одобрить / Отклонить** шаг агента; список шагов с классами и рисками.

### 3.10 Как задавать настройки на вашей машине

```bash
# разово, одной командой
python3 app.py --set ASM_PROFILE=pentest scan <цель>
# несколько сразу (каждый ключ своим --set)
python3 app.py --set ASM_PROFILE=pentest --set ASM_NUCLEI_RATE=60 agent extend 1 --scan 3
# посмотреть всё
python3 app.py --settings
```

## Что в итоге

Инструмент доведён до состояния «работает и заканчивается там, где нужно»:
разведка → вход → **стоп и передача доступа**. Непроверенным осталось ровно
одно большое место — **всё, что после входа** (стенд и ваша машина), и одно
маленькое — **`taskkill` на Windows**. Всё остальное — либо уже сделано, либо
ждёт вашего решения, и оба списка выше.
