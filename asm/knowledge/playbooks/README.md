# Плейбуки: формат и проверка

Плейбук — это правило «если на объекте видно **вот это**, то агент предлагает
**вот такую** цепочку шагов». Он не выполняется сам: каждый шаг всё равно
проходит через одобрение оператора.

Здесь лежат файлы `*.yaml` (или `*.json`). Проверить свои:

```bash
python3 app.py kb playbooks     # список плейбуков и замечания к ним
python3 app.py kb status        # сколько загрузилось, что не принято и почему
```

Проверка **строгая намеренно**. Опечатка в имени поля не падает — плейбук
загружается, никогда не срабатывает, и в разгар аудита это выглядит как
«инструмент ничего не предложил». Поэтому закрыт не только смысл, но и набор
полей.

## Как выглядит

```yaml
- id: linux-ssh-exposed          # строчные латинские буквы, цифры, «-», «_»
  title: SSH наружу              # как это называется для человека
  note: Необязательное примечание.
  match:                         # когда срабатывает
    port: 22                     #   номер порта (число или список)
    banner: ssh                  #   подстрока в баннере (без учёта регистра)
  steps:                         # что предложить
    - action: enum_services      #   имя действия из каталога агента
      why: точная версия OpenSSH — по ней отсекается большинство CVE
```

## Что проверяется

| правило | почему |
|---|---|
| поля плейбука — только `id`, `title`, `note`, `match`, `steps` | `stpes` вместо `steps` молча ничего не делает |
| `match` — только `port`, `service`, `product`, `banner` | `ports:` не совпадёт никогда, и это не будет ошибкой |
| типы: `port` — число или список чисел, остальные — непустые строки | `port: http` не сработает ни разу |
| `match` не пустой, хотя бы одно условие | плейбук без условий срабатывает на всём |
| у шага есть `action` и `why` | без `why` оператор одобряет шаг вслепую |
| `action` известен каталогу агента | иначе шаг некуда деть |
| `action` не из запрещённых | получение доступа решает оператор, а не шаблон |
| `id` не повторяется между файлами | два одинаковых id неразличимы в журнале |

## Чего в плейбуках не бывает

Действий, которые добывают доступ (`handoff_access`), и всех внутренних шагов
(они ставятся вручную, по одному хосту и с записанным доступом). Это не
ограничение формата, а правило проекта: шаблон предлагает разведку и проверки,
вход внутрь — решение человека.
